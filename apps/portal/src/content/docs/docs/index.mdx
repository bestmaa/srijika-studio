Srijika is a **CLI-first toolchain for a code-first React application studio**.
Create a complete project directly from npm; then use a terminal, VS Code,
Codex/MCP, or optional Desktop Studio against the same source and architecture
rules.

```bash
npm create srijika@latest my-app
cd my-app
npx @srijika/cli dev
```

Desktop Studio is not required. Restricted, typed `.ui.tsx` remains the only
persisted UI source of truth whenever the visual workbench is used.

:::caution[Public alpha]
The current milestone is a working code-first UI foundation. Rust-backed generated APIs and business logic are planned for Phase 2; they are not part of the current product.
:::

## The core promise

Visual tooling must never silently replace developer-owned code with a hidden format. Srijika permits an operation only when it can produce a bounded source edit, validate the expected content hash, compile the resulting TSX, and pass the same rules used everywhere else.

```text
.ui.tsx source
  → restricted non-executing compiler
  → diagnostics + stable source map + validated UiDocument
  → hierarchy + Inspector + React preview
  → bounded source edit intent
  → hash-checked save
  → compile again
```

## Recommended path

1. Follow [Getting started](/docs/getting-started/) to create the first project from npm.
2. Use the [CLI-first workflow](/docs/cli-runtime/) for terminal creation and runtime commands.
3. Follow the [VS Code workflow](/docs/vscode/) for Structure, context creation, diagnostics, tasks, and MCP.
4. Read [Product status](/docs/product-status/) to establish the current boundary.
5. Follow [Using Srijika Studio](/docs/using-studio/) only when you want the optional visual workbench.
6. Learn [Project anatomy](/docs/project-anatomy/) and the ownership rules.
7. Study the [Authoring model](/docs/authoring-model/) for `.ui.tsx` and connectors.
8. Read [Architecture](/docs/architecture/) before extending the compiler or native boundary.
