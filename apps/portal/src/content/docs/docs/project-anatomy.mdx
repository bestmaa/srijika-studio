## Canonical structure

```text
src/
├─ features/
│  └─ home/
│     ├─ Home.ui.tsx
│     ├─ Home.connector.tsx
│     ├─ home.store.ts
│     ├─ hooks/
│     │  └─ useHomeData.ts
│     └─ slots/
│        └─ navigation/
│           ├─ Navigation.ui.tsx
│           ├─ Navigation.connector.tsx
│           ├─ navigation.store.ts
│           ├─ hooks/
│           └─ parts/
│              └─ navigation-item/
│                 ├─ NavigationItem.ui.tsx
│                 └─ NavigationItem.connector.tsx
└─ shared/
```

## What each owner means

### Feature

A feature is the highest private product capability in the generated application. It owns its root visual contract, optional connector, feature-wide state, reusable feature logic, and named slots.

### Slot

A slot is a named visual region composed into its feature. It can own private wiring, state, hooks, and smaller implementation parts. A slot must not import another sibling slot's private code.

### Part

A part is a smaller implementation detail belonging to one slot. Part state and hooks remain private to that part subtree.

### Shared

`src/shared` is deliberate cross-feature code. It is not a shortcut around unclear ownership. Code moves there only when multiple features genuinely share the same stable capability.

## Capability flow

```text
ancestor-owned capability  ──✓──> descendant
private child capability   ──✗──> parent or sibling
feature-private capability ──✗──> another feature
```

If siblings need the same state or hook, promote it to their nearest common owner. If multiple features need it, promote it deliberately to `src/shared`.

## Complexity limits

- Maximum 200 meaningful lines in the exported UI function.
- Maximum 300 meaningful lines in one `.ui.tsx` file.
- Maximum 16 top-level contract members across data, events, and slots.

When UI exceeds a limit, extract a meaningful slot or part. When state crosses an ownership boundary, promote its owner instead of bypassing the architecture.
